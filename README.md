# LiveMatrix — 同屏多直播

跨平台桌面应用（Windows / macOS）：**一个主窗口 + 最多 7 个副窗口**同屏观看不同直播，仅主窗口播放声音，支持哔哩哔哩、抖音两个平台的扫码登录（登录状态自动记忆）。

## 功能特性

- **16:9 观影布局**：主窗口以 16:9 打开并保持该比例缩放；界面为 4×4 网格，主窗口占左上 3×3，副窗口最多 7 个，**均匀分布在主窗口右侧（3 格）与下方（4 格）**——16:9 窗口下每个画面都近似 16:9。
- **B站直播直连播放**：哔哩哔哩直播间不加载平台页面，由主进程调用直播开放接口（携带已登录 Cookie）直接解析拉流地址，渲染层用 mpegts.js（HTTP-FLV，延迟最低）/ hls.js（HLS 回退）在自研 `<video>` 格子里播放——画面精确铺满格子、资源占用远低于整页浏览器，清晰度随登录状态自动解锁（实测未登录也可拿到原画）。流地址过期或断线时自动重新解析续播；解析失败（如未开播、接口变动）自动回退为内嵌页面模式。
- **抖音页面内嵌 + 纯净模式**：抖音直播以内嵌页面展示（接口有签名防护，暂不直连），打开后自动触发「网页全屏」并隐藏礼物栏、聊天区、活动浮层等非视频元素；若改版导致自动全屏失败，会自动降级为「播放器强制铺满」。
- **只有主窗口有声**：副窗口始终静音；把某个副窗口换到主窗口槽位后，声音自动切换到它，画面**不刷新、不中断**。
- **添加直播**：工具栏「＋ 添加直播」按钮弹出对话框，粘贴直播间地址即可（自动识别平台）。副窗口达到 7 个上限后按钮自动禁用，计数 `N/7` 实时显示。
- **双击置换**：双击任意副窗口，它即与主窗口互换位置并接管声音，原主窗口变为静音；直播画面在置换过程中不刷新、不中断。
- **双击铺满（焦点模式）**：双击主窗口，主画面铺满整个程序界面（副窗口隐藏但直播不中断）；再次双击回到多窗口同屏布局。
- **平台登录**：工具栏提供哔哩哔哩 / 抖音登录入口，扫码登录后 Cookie 持久化保存，重启不丢失；随时可退出登录。
- **无边框简约深色界面**：无系统标题栏与菜单栏，工具栏左侧区域可拖动移动窗口（双击可最大化/还原），右上角为自绘的最小化 / 最大化 / 关闭按钮。
- **每次启动全新布局**：直播窗口不跨启动保留，重启后回到空白界面重新添加；平台登录状态则会一直保留。

## 技术选型：Electron

在 Tauri 与 Electron 之间选择了 **Electron**，核心理由：

| 需求 | Electron 能力 | Tauri 的局限 |
| --- | --- | --- |
| 单窗口静音/有声切换 | `webContents.setAudioMuted()` 跨平台可靠 | 系统 WebView（macOS WKWebView）无统一静音 API |
| B 站 / 抖音页面兼容 | 内置 Chromium，内核行为与主流浏览器一致 | WKWebView / WebView2 对抖音登录、播放器兼容风险高 |
| 按平台隔离并持久化登录 | `session.fromPartition('persist:…')` 开箱即用 | 多 WebView 共享 Cookie 存储，隔离不便 |

架构：主进程用一个 `BrowserWindow` 承载 UI 层（网格、对话框、工具栏）。直播格分两种：**直连格（B站）**——主进程经 `electron/bili.ts` 调用无签名公开接口（`get_info` 换真实房间号 + `getRoomPlayInfo` 拿拉流地址，请求带 `persist:live-bilibili` 分区 Cookie），渲染层用 mpegts.js（FLV）/ hls.js（HLS）在 `<video>` 里播放，CDN 的 Referer 校验由主进程 `webRequest.onBeforeSendHeaders` 注入解决；**内嵌格（抖音 / B站回退）**——独立 `WebContentsView` 叠放在格子上，渲染层把各格坐标经 IPC（`layout:update`）上报 `setBounds` 并附 `isMain` 控制静音。两种格子混排于同一网格，互换/铺满时 DOM 节点整体搬移，播放不中断。直连格的交互（双击互换/铺满、右上角关闭）走 DOM；内嵌格注入 `stream-preload`（隔离世界、捕获阶段）拦截真实双击并在页面内挂关闭按钮。地址对话框打开期间主进程把全部内嵌视图缩为 0（`WebContentsView` 层级高于 UI DOM），关闭后按记忆位置恢复。内嵌格打开后注入平台脚本（`electron/enhance.ts`）自动进入网页全屏并净化界面，播放器容器带 CSS 居中规则保证小格子里画面居中。

## 环境要求

- 开发：Node.js ≥ 20.10，pnpm ≥ 10（`npm install -g pnpm` 安装）
- 运行：Windows 10+（x64）或 macOS 12+（x64 / Apple Silicon）
- 打包 macOS 安装包必须在 macOS 上执行（系统限制）

## 快速开始

```bash
pnpm install        # 安装依赖（国内网络可先执行：export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/）

pnpm run dev        # 开发模式（Vite 热更新 + Electron）

pnpm run build      # 编译主进程 + 打包渲染层到 dist/
pnpm start          # 构建并以生产模式运行
```

## 打包脚本

| 命令 | 产物 | 说明 |
| --- | --- | --- |
| `pnpm run dist:win` | `release/LiveMatrix-Setup-1.0.0.exe` | Windows NSIS 安装器（x64），可选安装目录、创建桌面快捷方式 |
| `pnpm run dist:mac` | `release/LiveMatrix-1.0.0-arm64.dmg` / `-x64.dmg` | macOS 双架构 DMG，需在 macOS 上执行 |
| `pnpm run dist:all` | 以上全部 | — |

打包环境说明：在 **Windows** 上打 NSIS 安装包开箱即用；在 **Linux**（CI 交叉打包）需要 wine（`sudo apt-get install -y wine`）；macOS 的 DMG 只能在 macOS 上生成（系统限制）。

自定义图标：把 `icon.ico`（Windows）和 `icon.icns`（macOS）放到 `build/` 目录后重新打包即可；未提供时使用默认图标。当前 DMG 未做签名（`mac.identity: null`），分发给他人时 macOS 首次打开需在「系统设置 → 隐私与安全性」中允许；正式分发建议配置 Apple 开发者证书签名。

## 使用说明

1. **首次使用先登录**（可选，但抖音多数直播间要求登录才能观看）：
   点击工具栏的「哔哩哔哩 未登录」或「抖音 未登录」标签，在弹出的窗口中扫码登录。登录成功后窗口自动关闭，标签变为绿色「已登录」。登录状态保存在本机，重启无需重复登录；点击「已登录」标签可退出登录。
2. **添加直播**：点击右上角「＋ 添加直播」，粘贴直播间地址，例如：
   - 哔哩哔哩：`https://live.bilibili.com/21452505`
   - 抖音：`https://live.douyin.com/745969462470`
   确认提示「已识别：哔哩哔哩/抖音」后点「添加」。B站直播间会先在后台解析直连流地址（约 1-2 秒），随后以自研播放器直接播放视频流；抖音以内嵌页面展示。第一个添加的直播进入主窗口（左上角，有声），之后添加的依次填入主窗口右侧与下方的副窗口格（静音）。
3. **置换窗口**：双击任意副窗口画面，它与主窗口互换位置——新主窗口接管声音，原主窗口变为静音，直播画面在置换过程中不会重新加载。
4. **铺满 / 还原**：双击主窗口画面，主画面铺满整个程序界面，副窗口暂时隐藏（直播不中断）；再次双击主窗口或按 `Esc` 回到多窗口同屏布局。
5. **关闭窗口**：鼠标移到直播画面右上角，出现半透明 × 按钮（悬停变红），点击即关闭该窗口。关闭主窗口后，第一个副窗口自动升为主窗口。
6. **每次启动回到空白布局**：直播窗口列表不做跨启动记忆，重新打开程序后重新添加即可；平台登录状态保留，无需重新扫码。

## 常见问题

- **抖音直播间黑屏 / 提示登录**：抖音直播通常要求登录，请先完成抖音扫码登录。
- **B站窗口以页面形式打开**：直连解析失败（未开播、接口临时变动等）时会自动回退为内嵌页面模式，属正常兜底；开播后重新添加即可回到直连播放。
- **B站直连画面中断/显示「线路刷新中」**：拉流地址有时效，断线后应用会自动重新解析续播，无需手动处理；若长时间未恢复，关闭该窗口重新添加。
- **添加后一直「载入中」**：检查地址是否正确、直播间是否正在直播；也可能是网络问题，可关闭该窗口后重新添加。
- **画面与格子错位**：应用内禁用了页面缩放（Ctrl/Cmd + ±），请勿通过系统辅助功能强制缩放；正常缩放主窗口不会错位。
- **副窗口画面两侧有窄黑边**：属正常现象。副窗口格子的宽高比略宽于 16:9，视频等比缩放居中后会保留左右细边；画面始终居中平铺。
- **最多能开多少个**：1 个主窗口 + 7 个副窗口，共 8 路；达到上限后添加按钮与占位格均提示禁用。
- **如何在开发区分平台登录数据**：分别存放在 `persist:live-bilibili` 与 `persist:live-douyin` 两个 session 分区（位于系统用户数据目录），互不干扰。
- **在 WSL/WSLg 中运行出现中文方块（豆腐块）**：系统缺少中文字体，执行 `sudo apt-get install -y fonts-noto-cjk` 后重启应用即可；Windows / macOS 无此问题。

## 目录结构

```
live-matrix/
├── electron/               # 主进程（TypeScript → dist/electron）
│   ├── main.ts             # 窗口/视图管理、布局与静音、登录、直连解析调度、Referer 注入、双击中继
│   ├── bili.ts             # B站直连：房间号归一化 + 拉流地址解析（带登录 Cookie）
│   ├── preload.ts          # contextBridge 暴露的安全 IPC API
│   ├── stream-preload.ts   # 注入内嵌直播视图：捕获真实双击（互换/铺满）+ 页面内关闭按钮
│   ├── platforms.ts        # 平台识别、登录页地址、session 分区（纯逻辑，渲染层共用）
│   └── types.ts            # 共享类型
├── src/                    # 渲染层 UI（Vite → dist/renderer）
│   ├── main.ts             # 网格布局、添加对话框、直连播放器（mpegts/hls）、双击互换/焦点模式、登录标签
│   ├── ui.css
│   └── lm.d.ts
├── index.html              # 主界面
├── electron-builder.yml    # Windows/macOS 打包配置
└── package.json            # dev / build / dist:win / dist:mac 脚本
```
